# 🚄 车票最优助手（kunle）

> 把 12306 的车次截图粘进去，自动算出**最划算的买法**和**最省时的走法**。

不上传、不抓取、不登录。截图在你本机用 Windows 自带的 OCR 引擎识别，方案计算全部在浏览器里完成 —— 工具只做一件事：**在你给的车次里，找出价格与时间的最优组合。**

---

## 为什么这样设计

买火车票有两个常见纠结：

1. **怎么买最划算？** 直达票往往不是最便宜的。北京→上海直达二等座 553 元，而「北京→南京 + 南京→上海」两程合计可能更便宜、甚至更早到。人肉比价几乎不可能。
2. **怎么走最省时？** 车次表只给单趟历时，不告诉你换乘要等多久、总耗时多少。

早期版本曾直接调用 12306 查询接口，但 12306 的用户协议明确禁止自动化抓取，接口也布有反爬机制。**这个版本把数据来源交还给你**：你自己从官方 App 截图，工具在本地识别、本地计算。既不违反条款，也不需要任何账号或 API Key。

---

## 它是怎么工作的

```
你的截图 ──► 本机 Node 服务 ──► Windows.Media.Ocr（离线中文识别）
                                      │
                                      ▼
                              解析成车次表格（可人工修改）
                                      │
                                      ▼
                     浏览器内计算：最便宜 / 最省时 / 综合最优 / Pareto 前沿
```

三个关键点：

| 环节 | 实现 | 是否联网 |
|---|---|---|
| 截图 → 文字 | Windows 自带 `Windows.Media.Ocr`（与系统截图工具提取文字同款引擎） | ❌ 完全离线 |
| 文字 → 车次表格 | `assets/parse.js`，按坐标聚类行、容错修正 OCR 错字（`G1`→`GI`、`598.0`→`598·0` 等） | ❌ |
| 计算方案 | `assets/algo.js`，纯数学：归一化打分 + Pareto 支配关系 | ❌ |

**不会发生的事**：不请求 12306、不上传你的截图、不收集任何信息。

## 功能

- 📷 **截图识别**：点击选择 / 拖拽 / `Ctrl+V` 粘贴，自动识别车次、时刻、历时、票价、余票
- ✏️ **表格可编辑**：OCR 难免有错字，识别结果直接进表格，改完再算
- 🚄 **直达 + 中转组合**：把 A→中转 的车次标为「第一程」、中转→B 标为「第二程」，自动生成可行组合
- ⏱ **换乘时间校验**：可设最少换乘分钟（默认 30）与最长等待（默认 480），不合理的组合直接淘汰
- 🏷 **三类结论**：最划算（总价最低）、最省时（含换乘等待的最短总耗时）、综合最优（按权重加权）
- 📈 **Pareto 前沿**：标出「没有被任何方案在更便宜和更快上同时超越」的方案
- 🎚 **权重滑块**：在「省钱 ↔ 省时」之间滑动，推荐结果实时重算
- 🔗 **链接直达**：`?demo=1` 一键载入示例数据

## 快速开始

需要 Node.js 18+ 与 Windows 10/11（自带中文 OCR）。

```bash
git clone https://github.com/Kunle78778/kunle.git
cd kunle
node server/server.mjs
```

打开 <http://127.0.0.1:8787>，然后：

1. 从 12306 官方 App 截一张车次列表图（保证「车次 + 发到时间 + 票价」在同一行）；
2. 在页面上按 `Ctrl+V` 粘贴，或拖进虚线框；
3. 表格里核对、修正识别结果；
4. 点「计算最优方案」。

想先看效果：打开 <http://127.0.0.1:8787/?demo=1>。

### 没有 OCR 也能用

- 直接「粘贴文本」：每行一趟车，字段顺序随意，例如
  ```
  G1 北京南 上海虹桥 06:30 11:24 04时54分 二等座 有 ¥598.0
  G531 北京南 上海虹桥 06:08 12:04 05时56分 二等座 2 ¥498.0
  ```
- 或手动点「+ 添加一行」逐条填。
- 部署到 GitHub Pages 这类纯静态环境时，只有截图识别不可用（需要本机服务），粘贴文本与全部计算功能照常工作。

## 接口

本地服务只有两个端点：

| 端点 | 说明 |
|---|---|
| `GET /api/health` | 返回 `{ ok, ocr }`，用于页面显示引擎状态 |
| `POST /api/ocr` | 请求体为图片二进制（≤12MB），返回识别出的文字行及坐标 |

`POST /api/ocr` 返回示例：

```json
{
  "ok": true,
  "width": 1680,
  "height": 640,
  "lines": [
```

## 算法说明

### 综合最优

把价格与总耗时分别归一化到 `[0,1]`：

```
价格分 = (price - minPrice) / (maxPrice - minPrice)
时间分 = (duration - minDuration) / (maxDuration - minDuration)
综合分 = 权重 × 价格分 + (1 - 权重) × 时间分      ← 越小越好
```

权重由滑块给出，100 表示只看钱，0 表示只看时间。

### Pareto 前沿

方案 A 支配方案 B，当且仅当 A 同时满足 `价格 ≤ B 价格`、`时间 ≤ B 时间`，且至少一项严格小于。不被任何方案支配的，就是性价比前沿。

### 中转判定

```
等待时间 = 第二程发车 − 第一程到达（跨夜自动 +24h）
可行条件 = 最少换乘分钟 ≤ 等待时间 ≤ 最长等待
总耗时  = 第一程历时 + 等待时间 + 第二程历时
总价    = 第一程票价 + 第二程票价
```

## 已知限制

1. **OCR 不是 100% 准确**：字体太小、截图压缩过度时可能认错字。识别结果进表格后请核对，这一步是设计的一部分。
2. **需要 Windows**：OCR 依赖 `Windows.Media.Ocr` 与中文语言包；macOS/Linux 上只能用粘贴文本或手动录入。
3. **只算一次中转**：两次及以上换乘的组合数会爆炸。
4. **票价需你截图时就在场**：工具不替你查价，价格来自你提供的截图。
5. **不校验真实性**：算法只做优化，不验证车次是否存在、是否已售完。
